# 中文医疗信息工作台（frontend-v3）

## 入口和范围

- `/`：项目介绍首页，默认展示 A 浅色空间风格，右上角可切换 B 深色沉浸风格；
  中央分为「直接提问」与「患者工作台」。输入后明确发送才启动新会话；
  只打开首页不会请求患者、会话、健康检查或模型。
- `/workspace/`：中文工作台，配色跟随介绍页选择的 A/B 主题；`/workspace` 会重定向。
  可以收藏此地址直接使用；未选择主题时默认 A。
- `/classic/`：经典版 frontend-v2；仅更新可见品牌文案，原样式和交互保留。`/classic` 会重定向。
- `/api/*`：保留原业务接口，新增只读 `/api/patients*`，不新增数据表、不修改 Agent 编排或模型配置。
- 新旧界面使用同一后端会话数据。删除会话会同时影响两套界面。
- UI 专业化不代表已具备用户隔离、组织权限、临床验证或医疗合规能力。

项目介绍页是 `frontend-v3/landing.html`，独立样式在 `css/landing.css`，
装饰动效与链接过渡在 `js/landing.js`，双模式与显式提交在 `js/landing-entry.js`
（只有发送后才加载工作台代码）。
工作台入口仍是 `frontend-v3/index.html`，样式在 `css/workspace.css`，
交互在 `js/app.js`，HTTP/SSE 解析在 `js/api.js`，安全 Markdown 渲染在
`js/render.js`，工具中文名称与任务模板在 `js/catalog.js`。

## 工作台启动回归修复（2026-10-05，boot2）

用户反馈从首页进入后出现“工作台启动异常”，图标、任务卡片、历史和输入框无法正常初始化。
检查本机 8001 服务发现：HTML 设置了 `no-store`，但 FastAPI 的 JS/CSS 静态响应没有设置
缓存策略；主脚本有新版本号，内部 `verification.js` 等模块却仍使用无版本地址。

用真正的浏览器 HTTP 缓存复现旧 `verification.js` 升级到新主脚本时的失败：
`SyntaxError: The requested module './verification.js' does not provide an export named 'checkLabel'`。
模块链接在执行工作台初始化前就失败，因此页面按钮一直锁定；不是模型或 FHIR 调用失败。
该复现与用户截图一致，但没有直接读取用户浏览器中的缓存内容。
此前浏览器测试使用全新上下文，并使用请求路由拦截（会禁用 HTTP 缓存），漏掉了这个升级场景。

修复内容：

- 页面、入口脚本和整个 ES module 依赖链统一为 **`20261005-boot2`**，不再只给主脚本加版本。
  自动化测试检查每个本地 import 的版本与工作台入口一致。
- `app/frontend.py` 中新版静态资源的 200/304 响应补充 `Cache-Control: no-store`，与现有 Nginx
  策略一致。新版本地址先绕过已经存在的旧缓存；单独修改服务器缓存头不能清掉客户端已有缓存。
- `js/startup.js` 为启动失败提供“重新打开工作台”“返回首页”。恢复工作台会显式加载新文档，
  不能只更改 hash，否则失败的模块缓存仍留在原文档。恢复只打开会话管理，不自动提交或重放问题。
- 区分“脚本加载失败、尚未调用 start”和“已进入初始化、任务状态未确认”。前者保留内存中的
  首问供复制，后者不声称任务未发送。不会把草稿或问题写入 URL、浏览器持久化存储。
- 工作台 HTML 输入框初始禁用，初始化完成后解锁，避免脚本尚未装载时看似可用、实际没有事件处理；
  也避免原生 hash 焦点过早落到输入框，使键盘操作早于事件绑定。启动失败时保留只读输入以便复制。
- 首页初次 `pageshow` 不取消正在进行的进入动画导航；只有 bfcache 恢复才重置导航状态，
  避免慢模块加载期间点击入口后，迟到的页面事件把点击取消。动效外观不改变。

本轮没有改变首页外观、主题配色、患者业务逻辑、模型配置、医疗工具或数据库。
`patients.js` 和 `workspace.js` 仅更新 import 地址。没有推送 Git、重建容器或手动重启业务服务。

## 回答阅读与详情分层（2026-10-05，阶段 A）

### 可见变化

- **回答优先**：调整正文阅读宽度、标题层级、列表间距和表格样式，复制、详情、反馈放在回答下方。
  不改写模型返回的正文，不添加人为逐字播放。
- **执行过程收起**：回答下方显示工具调用次数，展开查看中文工具名与真实的已发起状态。
  参数移到详情面板，不在正文旁重复铺开。接口仍没有单工具完成事件，不显示虚构成功或单工具耗时。
- **详情绑定当前选择的回答**：顶部显示关联问题、第几条回答和正在生成 / 回答已返回 / 中断 / 历史状态。
  新一轮生成不会覆盖用户正在阅读的旧回答详情。
- **阅读提示在前**：原样展示接口免责声明；明确报告未通过的项，以及药物、过敏、敏感信息、剂量检查的
  非空提示列表提供跳转按钮。点击只展开对应检查，不再次请求模型或工具。提示数量不是医学风险数。
  元数据、评分、校验或耗时缺失时单独提示，不据此推断患者缺少检查或存在疾病。
- **中文校验项**：原顺序和全部返回项保留；摘要的“接口报告通过 / 未通过”只认严格布尔值，
  字符串 `"false"` 不当作布尔值。没有通过状态就明确标注，没有通过不等于不安全，报告通过也不是临床安全保证。
  展开先看中文字段，再按需展开完整字段 JSON；未知字段、长列表、数值、布尔值、文本原文不删减。
- **详细信息默认收起**：保留系统校验评分、后端报告耗时、完整工具事件（含参数），并提供完整最终返回数据 JSON。
  评分仅按原 `confidence` 显示百分比，不从内部因子重算、不按阈值生成临床结论；耗时不冒充浏览器全链路延迟。
  历史只能显示当时保存的元数据，不补造旧消息详情。

流式 token 只刷新正文，不反复重建详情 DOM；工具事件或最终结果到达时，同一回答保留技术详情的
展开状态、滚动位置与摘要键盘焦点。切换不同回答重置展开状态。断流保留已有正文，提示后台状态
可能未知，不自动重发。手机继续采用详情覆盖面板，Escape 关闭并返回触发控件。

## 首页双入口与患者工作台（2026-10-04，阶段 B）

本节记录阶段 B 的入口与患者工作台；回答展示以阶段 A 为准。
阶段 B 保留首页主标题、品牌、A/B 主题与分子动效，未改经典版、模型编排、
聊天详情或写入工具；回答/结果展示已在后续阶段 A 实施。

### 如何使用

- **直接提问**：首页输入是真实文本框，点击发送或 Enter 后进入工作台并发起一次新会话。
  不继承当前标签页的旧会话；之后的追问沿用本次会话。Shift+Enter 换行，中文输入法选词不发送。
- **继续已有会话**：首页下方链接仍是普通 `/workspace/#message-input` 导航，恢复标签页已有会话，
  不自动提问；会话管理功能保留。
- **患者工作台**：切换首页模式后点击「查找患者」，或点击侧栏「患者工作台」。
  按姓名或 FHIR 患者 ID 搜索，核对姓名、ID、出生日期后明确选择。没有选择前不加载临床详情。
- 首页四个资料链接分别直达选择流程的患者概览、用药与过敏、检验记录、病史记录栏目；
  选择患者后才展示目标栏目，不自动执行 AI 分析。更换患者立即清除旧详情，迟到响应不能覆盖新患者。
- 患者身份在详情页保留；加载中、未返回记录、资料不可用分别展示。模拟源明确标识为
  「演示数据 · 非真实病历」。空结果不表示已确认没有疾病、过敏或风险。

患者列表每次最多展示 20 位候选，提示是否还有结果，需要缩小搜索条件；不是全库浏览或分页。
各临床子类最多取 100 条，检测到后续页会提示还有未展示记录，不声称已读取完整病历。
已加载资料仅留在当前页面内存；更换患者后重读，刷新页面需重新选人，不把患者 ID 放入网址。

### 数据链路与边界

| 页面 | 新增 GET 接口 | 数据来源 |
| --- | --- | --- |
| 候选列表 | `/api/patients?q=...&limit=20` | FHIR Patient 搜索/精确 ID 读取 |
| 患者概览 | `/api/patients/{id}` | Patient 人口学资料与登记联系方式 |
| 用药与过敏 | `/api/patients/{id}/medications` | MedicationRequest、AllergyIntolerance |
| 检验记录 | `/api/patients/{id}/labs` | Observation，laboratory 类别 |
| 病史与就诊 | `/api/patients/{id}/history` | Condition、Encounter |

新文件 `app/api/patients.py` 复用现有 API Key 校验，并对响应添加 `no-store`；
`app/patient_records.py` 只调用现有 FHIR 客户端的 GET，不经过 LangGraph、模型、SQL 工具或医疗写入。
每次上游读取最长 6 秒；一次 API 的串行读取阶段最长约 12 秒，关联类别并发读取，未增加自动重试。
FHIR 客户端既有 OAuth 获取/刷新令牌仍可能请求令牌服务，这不是修改病历。
患者不存在、身份不匹配、资料引用归属不明或服务异常不会被当成正常空记录；
某个类别失败时，其他可用类别仍可显示。候选 ID 探测的明确 400/404 可回退姓名查询，
认证或服务器故障不静默吞掉。

本页**不调用** `care_gap_analysis`、`insurance_coverage_check`、`record_vitals` 等可能写入的工具。
但普通聊天仍有原来的工具能力，不能把只读页面解释为全站已禁用写入或具备患者级授权。
复用的 API Key 也不等于企业用户隔离。此页面不能公开暴露真实患者信息；
应用日志对新详情 URL 使用路由模板，但 Nginx、Uvicorn、HTTP 客户端等其他层的日志策略仍需部署侧管理。

检验页面只展示 FHIR Observation，不合并独立扩展表 `patient_lab_results`，不自动建表、导入记录、
判断异常或生成医学结论。未配置/不支持的源会显示不可用。内置 mock 未实现 Encounter，
该部分明确提示未提供，而不是伪装成患者没有就诊历史。缺失字段显示「未提供」，不请求模型补全。

### 首问交接、导航与前端文件

`landing-entry.js` 只在显式发送后获取同源工作台 HTML、本地样式和固定依赖，在同一文档中装载工作台，
以函数参数将问题传给 `app.js` 的一次性 `start({initialMessage})`。
这避免把患者问题塞入 URL、`history.state`、`window.name`、sessionStorage、localStorage，
也不新增服务端草稿存储。`workspace-entry.js` 负责普通工作台访问的初始化。
历史导航回到另一路径会加载对应文档，不重放首问；忙时禁止同页重复发送和栏目切换。
首页壳加载失败保留草稿且未提交；任务断流/失败后只提示状态，不自动重试或改走另一个聊天接口。

`js/patients.js` 管理候选、身份、四栏目和请求竞态，`css/patients.css` 复用现有颜色变量，
不新增 UI 框架、字体/CDN 或持久化存储。所有记录走纯文本展示。
阶段 B 当时的页面资源版本为 `20261004-patients1`（当前版本见阶段 A）；现有 Dockerfile 的目录 COPY 已覆盖新文件，
Nginx `/api/` 与静态入口无需新规则。

## 已接入的功能及边界

工作台医疗助手欢迎页的任务卡片和能力中心中的 14 个工具只填入可编辑模板，不自动发送，

`token`、`done`、`error`；按 80ms 节奏渲染已有文本，没有额外的逐字播放。
连接中断、非 2xx、协议错误或缺少 `done` 时保留部分内容并显示错误，
不会自动重试或转发到非流式接口。120 秒没有任何网络数据时停止接收，
明确提示后台任务可能仍在执行；这不是后端任务取消机制。

工具事件目前只报告开始，没有单工具完成事件。因此 UI 不显示虚构的
成功勾选、单工具耗时或来源链接。详情面板展示实际返回的工具参数、
校验结果、系统评分和 `latency_ms`。该耗时是后端报告值，不是浏览器
测得的全链路延迟；系统评分也不是医疗准确率。内容可能先于最终校验显示。

历史接口现在通过每条助手消息的 `metadata` 返回已保存的当轮详情，刷新或
